# 프로젝트 요구사항

기록일: 2026-10-29 (KST)

사용자가 대화에서 지정한 서비스 목표와 필수 기능을 기록한다. 이 문서는 요구사항 기록이며 구현 완료 또는 구현·DB 변경·배포·Git 작업 승인을 뜻하지 않는다. 평가 기준은 [심사 기준](EVALUATION_CRITERIA.md)을 함께 확인한다.

## 서비스 목표

지역의 문화·스포츠·여가 콘텐츠를 한곳에 모아 개인 맞춤형으로 추천하고, 사용자의 실제 참여를 마일리지와 지역 혜택으로 연결하는 지역 기반 참여형 플랫폼을 개발한다.

- 대상 지역: 대한민국 전국. 대도시뿐 아니라 소도시와 각 지역의 정보도 발견할 수 있어야 한다.
- 주요 사용자: 지역 주민, 여행객 등 모든 사용자.
- 지원 화면: PC와 모바일을 함께 지원하는 반응형 웹. PC 전용이라는 이전 요구는 변경되었다.
- 운영 목표: 실제 운영을 전제로 설계한다. 고정된 제출 기한은 아직 없으며 빠른 진행을 원한다.
- 협업 방식: 웹 개발을 처음 하는 팀도 이해하도록 문제의 원인·영향·해결 방법을 쉬운 한국어로 설명한다. 완료를 주장할 때 실제 검증 근거와 한계를 구분한다.

## 필수 기능과 순서

아래 순서는 사용자가 제시한 기능 순서다. 심사는 README의 주요 기능 순서를 따르므로, README 작성 시 일치시킬 필요가 있다. 현재 README는 보일러플레이트 상태이며 아직 갱신하지 않았다.

1. 마일리지 교환소: 지역 쿠폰과 혜택을 교환한다.
2. AI 맞춤형 지역활동 추천: 개인의 입력과 기록에 맞는 실제 지역활동을 추천한다.
3. 지역을 설명해주는 지도: 지역의 위치뿐 아니라 소개와 지역활동을 탐색할 수 있어야 한다.

추가 확장 요구(2026-10-29~30 KST): 17개 시도 아래 229개 시·군·구 선택, 14개 관심활동 분류, 포인트로 교환한 쿠폰을 눌렀을 때 바코드 표시. 쿠폰 소유자가 매장 직원에게 화면을 보여주고 확인창을 거친 뒤 한 번만 사용 완료 처리한다. 현장 활동은 현재 GPS로 위치를 인증하고 포인트를 적립한다.

방문·포인트 확장 요구(2026-10-29 KST): 사용자가 실제 활동에 참여한 뒤 방문 인증을 요청하고, 운영자 확인이 끝나면 활동별 포인트가 잔액과 원장에 적립된다. `MY > 방문 기록`에서 이전 방문의 활동명·날짜·확인 상태·적립 포인트를 다시 볼 수 있어야 하며, 같은 활동의 중복 인증과 회원의 잔액 직접 변경을 막는다.

지역 정보 추가 요구(2026-10-29 KST): 오류를 수정하고 지역별 축제·스포츠·음식점 정보를 추가한다. 기본 17개 탐색 지역 × 3개 분류 × 2개에 대표 축제 1개씩을 더해 축제 51개, 스포츠 34개, 음식점 34개로 확장했다. 모든 소지역에 각각 2개씩을 채운 상태는 아니다. 인천 지역 선택을 갱신해 소지역 선택지는 230개다. 실제 확인 수준과 출처는 [지역 카탈로그](REGIONAL_CATALOG.md)에 기록한다.

경북 보완 요구(2026-10-29 KST): 축제·스포츠 정보가 부족한 시·군에는 랜드마크와 대표 관광지를 추가한다. 경북 22개 시·군마다 여행·관광 명소 2곳씩 44개를 보완했다. 지도는 표시된 주소·장소로 검색하며, 최신 개방 여부·요금·시간이 미확인인 경우 그 상태를 안내한다.

카테고리 보완 요구(2026-10-29 KST): 기존 곳곳 웹사이트를 이어서 개선한다. 문화·예술, 공연·음악, 전시·박물관, 자연·생태, 공예·원데이, 역사·전통, 가족·키즈, 교육·배움, 봉사·커뮤니티, 웰니스·휴식에 장소·참여 안내를 각각 2개씩 추가해 총 183개로 보완한다. 각 항목의 지역·설명·공식 확인 링크·지도 검색어를 제공하며 최신 일정·가격·모집 상태의 미확인을 표시한다.

추가 보완 요구(2026-10-30 KST): 자료가 적은 위 10개 분류에 실제 기관·장소 안내를 각각 2개씩 더해 분류별 최소 4개, 독도를 포함한 총 204개로 확장한다. 공식 사이트에 접속해 최신 내용을 대조하지 못한 자료는 확인 완료로 표시하지 않는다.

세 기능은 반드시 포함되고 원활하게 작동해야 한다. 추천·지도·참여·적립·교환이 서로 연결되는 방향을 검토하되, 구체적 화면과 데이터 구조는 아직 확정하지 않았다.

## 추가 요청: 성별을 반영한 추천

- 사용자가 성별에 따라 추천하는 기능을 추가 요청했다.
- 제안한 설계 방향: 성별은 직접 선택하는 선택 항목이며 '선택 안 함'을 제공한다. 관심사·지역·일정·예산·활동 기록을 우선하고, 성별 반영을 끄거나 정보를 변경할 수 있도록 한다.
- 성별 고정관념으로 전체 활동의 검색·신청을 제한하지 않는다. 실제 참가 조건은 주최 측의 조건과 구분한다.
- 위 세부 정책은 제안 상태이며 입력 항목·보관·삭제·동의 방식은 구현 전에 확정한다. 성별을 이름이나 행동에서 추정하지 않는다.

## 디자인 논의 상태

- 사용자 요청: 폰트 추천과 다른 서비스의 디자인 비교.
- 제안 상태: Pretendard, 따뜻한 흰색·청록색·주황색, 사진 중심 탐색과 지도 연결, 명확한 마일리지 안내.
- 최종 디자인·폰트 채택은 아직 확정하지 않았다. 폰트 공식 문서와 라이선스는 조사했으나 비교 서비스의 최신 화면은 네트워크 제한으로 직접 확인하지 못했다.

## 설계 전에 해결할 항목

- 마일리지 적립·실제 참여 인증 방식, 적립 취소·교환 취소·환불·만료 정책.
- 제휴처 확보, 쿠폰 재고·발급·사용 확인과 부정 사용 방지.
- 전국 활동·지역 소개의 출처, 이용 조건, 갱신 주기, 소도시 정보 확보.
- 인증·DB·지도·AI 서비스 선택, 비용과 사용량 제한.
- 세 핵심 기능별 생성·조회·새로고침 후 유지·수정·삭제의 구체적 사용자 자료와 흐름. 추천 결과 저장이나 여행 계획 등을 어떻게 평가에 대응시킬지 미정이며, 확정 없이 충족했다고 주장하지 않는다.
- 심사용 계정과 데이터 준비, 배포 및 검증 방법. 비밀번호 등 비밀값을 문서에 기록하지 않는다.

## 현재 상태

최초 기록 시에는 요구사항과 평가 기준만 정리했다. 이후 사용자가 웹 구현을 요청해 임시 서비스명 '곳곳'으로 첫 웹 화면과 서버·SQL 코드를 작성했다. PC·모바일 탐색 및 미리보기를 검증했으며 실제 Supabase·AI·쿠폰 발급 연결은 아직 미완료다. 정확한 구현·검증 범위는 [웹 실행 안내](WEB_SETUP.md)와 [검증 기록](PLATFORM_TESTS.md)을 확인한다. 운영 DB 변경·유료 외부 호출·커밋·푸시·배포는 하지 않았다.

# 심사 기준과 근거 기록표

기록일: 2026-10-29 (KST)

사용자가 전달한 평가 문구와 배점을 아래에 보존한다. 전달자의 이름과 채팅 시각은 평가 내용에 필요하지 않아 제외했다. 해석과 프로젝트 적용 메모는 원문과 분리했다. 현재 모든 항목은 미검증이며 이 문서는 점수 획득을 보장하지 않는다.

## 코드 심사 — 50점

### 구동 — 10점

서비스가 열리고 로그인되며, 핵심 기능이 실제로 끝까지 되는가

세부 기준 5가지

- 열림·로그인 2점 — 서비스 주소가 휴대폰·PC 화면에서 열린다(1). 심사용 계정으로 로그인된다(1). (측정 프로그램이 잰다)
- 핵심 기능 1 2점 — README 「주요 기능」의 첫째 기능을 앱에서 해 본다(넣기 → 목록·결과에 보임 → 새로 고쳐도 남음 → 고치기·지우기). 코드도 화면 → 서버 → DB → 다시 읽기로 이어진다. 다 되면 2, 일부만 되면(넣기만, 새로 고치면 사라짐) 1, 안 되거나 박아 둔 예시 자료면 0.
- 핵심 기능 2 2점 — 「주요 기능」의 둘째 기능 — 기준은 핵심 기능 1과 같다.
- 핵심 기능 3 2점 — 「주요 기능」의 셋째 기능 — 기준은 핵심 기능 1과 같다.
- 하나의 서비스 2점 — 한 기능에서 만든 자료를 다른 화면·통계·AI 가 쓴다(1). 빈칸·잘못된 값을 넣어도 앱이 멈추지 않는다(1).

### 디자인 — 10점

예쁜가가 아니라 완성도 — 깨지지 않고 다듬어져 있으며 쓰기 쉬운가

세부 기준 4가지

- 깨지지 않음 3점 — 휴대폰(390px)·PC(1280px) 화면 사진에서 옆으로 넘치거나 잘리거나 겹치지 않는다. 글자를 읽을 수 있고 누르는 곳이 충분히 크다(WCAG 2.2 — 누르는 곳 24px 이상).
- 다듬어짐 3점 — 색·글꼴·간격·버튼 모양이 화면마다 같고, 제목·내용·버튼의 크기 차례가 분명하며 줄이 맞다. 템플릿 기본 화면·임시 글·깨진 그림이 없다.
- 쓰기 쉬움 2점 — 첫 화면에서 무슨 서비스인지 알 수 있고 핵심 기능으로 바로 간다. 버튼 이름만 보고 뜻을 알며, 뒤로 가기·취소가 된다.
- 상태 알림 2점 — 불러오는 중·빈 목록·오류·저장됨을 보여 주고, 누르면 바로 처리 중 표시가 나온다. 잘못 넣으면 그 칸 옆에 알려 준다.

### 반응속도 — 5점

로그인한 화면이 빨리 뜨는가(측정)와 느리게 만드는 코드가 없는가

세부 기준 2가지

- 측정 3점 — 로그인한 첫 주요 화면을 휴대폰 기준으로 3번 잰 Lighthouse 성능 점수(Chrome 에 든 구글 측정 도구, 100점 만점)의 가운데 값: 90 이상 3 · 70~89 2 · 50~69 1 · 50 미만 0. 경계에서 2점 안쪽이면 높은 구간으로 친다. (측정 프로그램이 잰다)
- 느린 까닭 2점 — 코드에서 느린 까닭을 찾는다 — 없으면 2, 하나면 1, 둘 이상이면 0: 줄이지 않은 큰 사진, 필요 없는 큰 라이브러리, 자료를 하나씩 기다리며 부름, AI 답을 기다리느라 화면 전체가 멈춤, 서버(Vercel)와 DB 의 지역이 다름.

### 로그인·보안 — 10점

로그인과 내 자료 지키기, 비밀값·입력 관리(OWASP Top 10:2025)

세부 기준 5가지

- 로그인 2점 — 검증된 로그인 서비스(Supabase Auth 등)를 쓰거나, 직접 만들었으면 비밀번호를 되돌릴 수 없게(해시) 저장한다. 로그아웃하면 보호된 화면이 열리지 않는다.
- 로그인 확인 2점 — 로그인하지 않고 보호된 화면 주소를 열면 로그인 화면으로 간다. 서버 기능도 로그인을 확인한다 — 버튼만 숨긴 것은 막은 것이 아니다.
- 내 자료만 2점 — 다른 계정으로 내 자료의 주소를 열면 보이지 않는다. 읽기·고치기·지우기마다 서버가 로그인한 사람의 것인지 확인한다.
- 비밀값 2점 — 저장소와 배포된 파일(브라우저가 받는 파일)에 비밀 키가 없다. 오류가 나도 화면에 내부 정보가 보이지 않는다.
- 입력 2점 — 서버에서 입력을 확인한다(브라우저의 확인은 건너뛸 수 있다). 사용자가 쓴 글을 HTML 그대로 화면에 넣지 않는다.

### 안정성·확장성 — 10점

여럿이 동시에, 오래·많이 써도 버티고 고치기 쉬운가 — 4분 시연으로는 안 보이는 것

세부 기준 3가지

- 여럿이 동시에 4점 — 함께 쓰는 자료가 DB 에 있다(서버 메모리·브라우저에만 두면 0). 정원·재고·좋아요 수가 동시에 눌러도 틀리지 않는다. 저장을 빠르게 두 번 눌러도 한 번만 저장된다. 바깥 서비스가 답하지 않으면 끝없이 기다리지 않는다.
- 오래·많이 써도 3점 — 자료가 많아도 한 번에 다 읽지 않고 나눠 읽는다. 목록 한 줄마다 DB 를 따로 부르지 않는다. 자주 찾는 칸에 색인이 있고 DB 구조를 바꾼 기록(마이그레이션)이 있다. 로그인이 만료되면 다시 로그인하라고 안내한다.
- 고치기 쉬움 3점 — 화면·서버 처리·DB·입력 확인이 나뉘어 있다. 한 파일·한 함수에 몰아넣거나 같은 코드를 복사해 붙이지 않았다. 쓰지 않는 코드·디버그 출력이 없다. README 와 .env.example 만으로 다른 사람이 실행할 수 있다.

### AI 기능 — 5점

서비스 안의 AI 기능(OWASP LLM Top 10:2025) — 없으면 0점

세부 기준 4가지

- 핵심·맞춤 2점 — 서비스의 핵심에서 AI 를 쓰고, 그 사람의 기록·입력을 넣어 답을 만든다. 흔한 대화창만 붙였으면 1.
- 답 가공 1점 — AI 답을 그대로 붙이지 않고 형식을 확인해 저장하거나 화면에 맞게 보여 준다.
- 늦거나 실패해도 1점 — 기다리는 동안 표시가 있고, 제한 시간과 실패 안내가 있다.
- 남용·비용 제한 1점 — 로그인한 사람만 쓰고, 한 사람이 쓰는 횟수와 글 길이를 제한한다.

### 공통 채점 규칙과 심사 방법

근거(코드의 파일·줄, 화면 사진, 써 본 기록, 측정값)를 대지 못한 칸은 0점입니다.

서비스가 열리지 않으면 구동은 코드로만 보고 4점까지 줍니다.

구동이 5점 미만이면 로그인·보안과 안정성·확장성은 각각 5점(절반)까지 줍니다 — 기능이 거의 없는 앱이 깔끔하고 안전하다는 것만으로 높은 점수를 받지 않게.

치명 결함이 있으면 로그인·보안은 3점까지 줍니다: 비밀번호를 그대로 저장함, 비밀 키가 브라우저로 나감, 로그인하지 않고 또는 남의 계정으로 자료를 보거나 고치거나 지울 수 있음.

로그인이 없으면 로그인·로그인 확인·내 자료만 세 칸은 0점, AI 기능이 없으면 AI 기능 항목은 0점입니다.

제출 마감 시점의 GitHub 저장소(코드)와 배포한 서비스를 AI가 모든 팀에 같은 기준으로 심사합니다. 측정 프로그램이 서비스를 열어 속도를 재고, AI가 「내 신청」의 심사용 계정으로 로그인해 직접 써 본 뒤 칸마다 근거(코드의 파일·줄, 화면 사진, 써 본 기록)를 대고 채점합니다. 코드는 이름·학번·연락처와 API 키 같은 비밀값을 가린 뒤 AI에 줍니다.

## 프로젝트 적용 메모 — 평가 원문과 구분

- 필수 기능은 [프로젝트 요구사항](PROJECT_REQUIREMENTS.md)에 기록한다. README의 주요 기능 순서는 심사 기능 순서와 직접 연결되므로 구현 확정 시 일치시킨다.
- 추천과 지도는 조회만으로 끝내지 않고, 각 기능의 평가 대상 자료와 생성·조회·유지·수정·삭제 흐름을 설계해야 한다. 구체적 대응은 아직 미정이다.
- 마일리지 거래 기록은 무조건 삭제 기능을 추가하기보다 무결성과 운영 정책을 검토하고, 평가에 대응하는 수정·삭제 대상과 취소 흐름을 명확히 해야 한다.
- Lighthouse는 로그인한 첫 주요 화면의 모바일 측정 3회와 중앙값을 남긴다. 비로그인 랜딩 페이지 점수로 대체하지 않는다. 측정 도구·설정·실행 시각·대상 배포 버전도 기록한다.
- 390px·1280px에서 주요 화면과 상태를 확인한다. 24px은 전달받은 심사 기준이며 WCAG 전체 준수나 인증을 뜻하지 않는다.
- OWASP 공식 문서와 적용 범위는 구현·보안 검토 때 별도 확인한다. 이 원문 기록만으로 해당 기준 준수를 주장하지 않는다.
- 두 계정과 비로그인 상태로 읽기·수정·삭제 권한을 검증하고, 쿠폰 동시 교환·중복 제출·AI 시간 초과·횟수 제한 등을 실제 확인한다.
- 증거에는 계정 비밀번호, 세션 토큰, API 키, 개인 정보를 담지 않는다. 코드 줄 번호는 제출 대상 커밋을 기준으로 갱신한다.

# 곳곳 기획 및 검증 기록

작성일: 2026-10-30 KST. 이 문서는 서비스 기획, 구현 확인, 자동 검사, 실제 운영 검증을 구분한다. 사용자 인터뷰·설문이나 매출·재방문율 조사를 수행한 것으로 작성하지 않는다.

## 1. 문제 정의와 서비스 목표

곳곳은 전국의 문화·스포츠·여가 정보를 발견하고, 장소 방문과 지역 혜택을 연결하는 지역활동 웹이다. 대도시뿐 아니라 소도시·군 지역을 포함하며 지역 주민과 여행객을 함께 대상으로 한다.

기획의 출발 가설은 세 가지다. 활동 정보가 여러 채널에 나뉘어 있어 조건에 맞는 장소를 찾기 어렵고, 작은 지역의 콘텐츠는 상대적으로 발견하기 어려우며, 활동 탐색이 실제 방문과 지역 내 소비로 이어지는 연결이 부족하다는 것이다. 이는 현재 팀이 검증하려는 문제 가설이며 전국 이용자를 조사해 입증한 통계가 아니다.

목표 사용자 흐름은 **지역·관심 분야 선택 → 장소와 일정 확인 → 방문 → 인증 → 마일리지 확인 → 지역 혜택 이용 → MY에서 기록 확인**이다.

## 2. 주요 이용 상황과 기능의 타당성

| 이용 상황                              | 필요한 기능           | 설계한 해결 방법                                                                                                     |
| -------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 주민이 가까운 주말 활동을 찾는다       | 탐색·검색·소지역 분류 | 시도·시군구·14개 활동 분야로 탐색하고 장소 상세와 확인 링크로 연결한다.                                              |
| 여행객이 처음 방문하는 지역을 알아본다 | 지역 지도·장소 정보   | 17개 시도 소개와 장소·주소 기반 네이버 지도 검색을 제공한다.                                                         |
| 활동 참여를 기록하고 혜택을 확인한다   | 곳곳드림·MY           | GPS 방문 확인, 마일리지 원장, 쿠폰 상태와 방문 기록을 연결한다.                                                      |
| 자신의 취향에 맞는 활동을 찾는다       | AI 맞춤 추천          | 입력·저장 기록과 실제 후보 ID를 기반으로 추천 이유를 생성하도록 서버 코드를 구성했다. 실제 AI 연결 검증은 남아 있다. |

차별화 목표는 지역 정보의 전국 단위 탐색, 개인 취향에 맞는 발견, 방문 기록과 지역 혜택을 하나의 흐름으로 연결하는 것이다. 지도·행사 안내·쿠폰 서비스의 기능을 참고한 기획상의 방향이며, 경쟁 서비스 전수 조사나 독점 기능을 입증한 결과는 아니다.

## 3. 현재 확인한 범위와 한계

- 공개 참고 콘텐츠 518개, 17개 시도, 14개 활동 분류를 제공한다. 지역별 데이터의 존재와 최신 운영·예약 가능 여부는 서로 다른 검증 대상이다.
- 공개 자료에서 좌표를 확보한 항목은 310개다. 현재 카탈로그의 가격은 미확인 상태이며 정형 영업시간 정보도 없어 실제 이용 가능·예산 충족을 보장하지 않는다.
- 지도는 지역 선택용 개략도다. 상세 화면의 네이버 지도 링크는 실제 장소·주소 검색이며 자체 길찾기·실시간 이동시간 서비스가 아니다.
- 공개 GitHub Pages는 체험 화면이다. 체험 로그인과 10,000P 지갑, 쿠폰 사용 차감은 같은 탭의 브라우저 저장 공간에서 작동한다. 실제 회원 인증·제휴 혜택 발급·운영 DB 적립과 구분한다.
- Node 서버 실행본에는 scrypt 비밀번호 해시, HttpOnly 세션, GPS 거리·정확도 검사와 중복 적립 방지 코드가 있다. JSON 저장소는 단일 서버의 개발·검증용 구성이다.
- Supabase SQL·RLS와 OpenAI 호출 코드는 준비되어 있으나 현재 작업 환경에 실제 연결 값이 없어 운영 DB·실제 AI 호출·공동 DB 동시성은 검증하지 않았다.
- 여행코스 추천은 후속 설계 단계다. 대중교통·도보 동선, 날짜·운영시간·예산을 반영하는 실제 여행 일정 생성이 완료된 것으로 표시하지 않는다.

## 5. 기술 검증과 재현 방법

이 기록과 함께 수행한 검사 출력·화면 사진은 [근거 폴더](evidence/planning-review/)에 보관한다. 검사 실행 결과를 원본 로그와 대조하고, 다른 환경의 성공으로 확대 해석하지 않는다.

| 검사                  | 재현 명령                                  | 확인 항목                                                                                             |
| --------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 체험 사용 흐름        | `node scripts/verify-preview-login.mjs`    | 로그인·새로고침·로그아웃, 10,000P 시작, 1,200P 사용 후 8,800P, 중복·잔액 부족·저장 실패, MY 사용 내역 |
| 실제 Express 경계     | `npm run auth:test`                        | 비밀번호 해시·세션, 익명 차단, GPS 거리·오차, 동시 중복 적립 방지, 계정 분리, 재시작 유지             |
| 외부 서비스 오류 처리 | `node scripts/verify-platform.mjs`         | 모의 전송으로 인증·시간 초과·횟수 제한·오류 정보 보호 확인. 실제 Supabase 연결 검사 아님              |
| 정적 미리보기         | `node scripts/build-web-preview.mjs`       | 현재 컴포넌트로 HTML 재생성. 서버 운영 기능을 배포하는 명령은 아님                                    |
| 코드 품질·빌드        | `npm run lint`, `npx next build --webpack` | 린트·TypeScript·Next 프로덕션 빌드                                                                    |

이 환경에서는 Prisma 엔진 다운로드가 차단된 이력이 있어 `npm run check`·`npm run build` 전체 스크립트와 직접 Next 빌드를 구분한다. Lighthouse 성능 점수, 실제 AI 응답 품질, 운영 DB 권한 검사에 대한 점수를 임의로 적지 않는다.

## 6. 이번 보완 사항

- 사용 완료 쿠폰을 MY에서 다시 열어 읽을 수 있게 하고 재사용 버튼은 비활성화한다.
- 곳곳드림에서 사용한 쿠폰을 ‘사용 내역 보기’로 구분하고 차감 완료 금액을 보여 준다.
- 쿠폰 사진이 미리보기에서도 영역을 채우도록 보완한다.
- 실제 AI 연결이 없는 체험 화면은 생성 버튼의 준비 상태와 활동 탐색 대안을 안내한다. 기존 실제 AI API와 입력·응답 검증은 유지한다.
- README의 기획·검증 역할에 수행 범위와 관련 근거 문서를 연결한다.

## 7. 실제 사용자·운영 검증 계획

다음 내용은 앞으로 수행할 계획이며 조사 완료 결과가 아니다. 지역 주민과 여행객을 각각 모집해 동의받은 과업 테스트를 진행하고, 개인정보를 최소화해 익명 결과를 기록한다. 첫 활동 찾기, 지도에서 위치 확인, 쿠폰 이용과 사용 기록 다시 찾기의 성공 여부·소요시간·오해한 문구를 관찰한다.

초기 개선 목표는 참가자의 80% 이상이 도움 없이 핵심 과업을 완료하는 것으로 제안한다. 이 수치는 목표이며 측정값이 아니다. 방문·재방문·실제 혜택 이용 효과는 제휴처·참여 확인·운영 데이터를 확보한 후 별도로 평가한다.

실제 서비스 공개 전에는 Supabase 인증·세션 통합, 사용자별 DB 권한, 제휴처와 재고·취소 정책, 최신 장소·가격·운영시간, GPS 보완 증빙, AI 비용 한도와 실제 응답, 로그인한 화면의 Lighthouse 3회 중앙값을 검증해야 한다. 현재 자동 검사 통과를 시장 수요 검증이나 심사 점수로 환산하지 않는다.
